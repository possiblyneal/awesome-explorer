## Purpose

The explorer app: an Express server that reads awesome lists, the operator's stars, and GitHub trending, and fetches metrics from GitHub, and a React UI that filters, sorts, and labels them.

## Ownership

Single operator. Runs longlived (`.unit.json`), started by `scripts/run`, which runs `npm run dev`; `npm start` serves the built UI in production.

## Local Contracts

- Layout:
  - `src/server/` — Node only. `github.ts` (fetch client, classifies rate limits vs refusals), `readme.ts` (list parsing, outbound link count), `metrics.ts` (GraphQL batch lookups, then each repository's star history and activity), `activity.ts` (per-repository issue and pull request searches: backlog, handle and merge times, unanswered and old open shares, committers), `star-lists.ts` (the operator's star lists), `health.ts` (labels and score), `store.ts` (SQLite: cached lists, metrics, README link counts, translations, plus trending dismissals, which are operator data and not a cache), `trending.ts` (trending page scraping and ranking), `translate.ts` (MyMemory client), `explorer.ts` (refresh queue, discovery), `config.ts`, `main.ts` (routes, Vite middleware in dev).
  - `src/web/` — browser only, built by Vite into `dist/web/`.
  - `src/shared/` — imported by both sides and the only code they share: `types.ts` (the API's JSON shapes), `index-list.ts` (the index list's name, and `STARS_LIST`, the key stars are viewed and cached under), and `translation.ts` (`mayNeedTranslation`, the check both sides run before asking for one).
- Node runs the TypeScript directly by type stripping, so server code uses only erasable syntax (`erasableSyntaxOnly`) and `.ts` import extensions. The dev server loads `vite.config.ts` with `configLoader: "native"` (see `docs/LESSONS.md`).
- Config: `GITHUB_TOKEN` (else `gh auth token`), `HOST` (default `127.0.0.1`), `PORT` (default `4321`), `NODE_ENV=production`, `MYMEMORY_EMAIL` (optional; raises MyMemory's quota to 50,000 characters a day). `npm start` and `npm run dev` read the unit's gitignored `.env` when present; the email lives there, never in source, since the repository is public. The cache is `state/cache.db`.
- Routes: `/api/lists/:owner/:name`, `/api/stars` (the token user's starred repositories, each with the star lists holding it, `#/stars` in the UI), `/api/trending` (`#/trending`), `POST /api/trending/:owner/:name/{dismiss,snooze}`, `DELETE /api/trending/:owner/:name` (undo, 204), `/api/translate?q=` (`{ text }` in English, 1–1000 characters), `/api/discover?q=`.
- List parsing reads bullet, numbered, and table lines, and `>` quoted lines that an item or link opens (a quoted tagline stays prose); a `---|---` divider marks the rows under it as a table even without leading pipes.
- Trending scrapes `github.com/trending` HTML (no API exists): 3 periods × `LANGUAGES` × `SPOKEN` in `trending.ts`, 8 pages at a time. Rows merge by repository with the best `gained / period days` as `starsPerDay`; `Explorer.trending` then replaces it with stars per day over the 7 whole UTC days before today (`starsPerDayLastWeek`, 2 weeks of star history per repository, 8 requests at a time, in-memory cache until 6h old or UTC midnight, waited on up to `RATE_TIMEOUT` (60 s) alongside the previews) and ranks by that. A missing or failed history falls back to the scraped weekly gain / 7, else monthly / 30, else the scraped best; a rate limit stops the remaining lookups. A markup change on GitHub breaks `parseTrending` silently; `tests/trending.test.ts` pins the row shape. `Explorer.trending` looks up each repository's `openGraphImageUrl` once per refresh (in-memory 1h cache, 100 aliased repositories per GraphQL query, all batches at once) and keeps it as `image` only when `usesCustomOpenGraphImage` is true; a failed lookup, a missing repository, or a lookup still running after `PREVIEW_TIMEOUT` (15 s) leaves `image` null and never fails trending. Each row carries its language swatch color (`languageColor`, null without a language; first seen wins on merge). The UI (`TrendingView.tsx`) shows a card grid (3/2/1 columns), 48 cards at a time with an IntersectionObserver sentinel adding 48 more; a card leads with the repository's uploaded social preview (2:1, cropped; an image that fails to load falls back to the avatar hero) and links to GitHub, and Snooze and ✕ hide it without opening the link, and a bottom undo bar (about 5 s) puts the last hidden card back at its index.
- Card descriptions are translated to English when the card first comes on screen (`useEnglish` in `TrendingView.tsx`, the original shown until then and on hover). Only text with a letter outside A–Z is sent, to MyMemory's free API (`autodetect|en`, 5,000 characters a day, 50,000 with `MYMEMORY_EMAIL`); its 403 "distinct languages" means already English. `Explorer.english` caches each translation in SQLite by source text for 7 days and shares one in-flight request per text; a failure answers the stale cached translation, else the original, and is asked again next time; MyMemory's `quotaFinished` counts as a failure.
- Discovery keeps a search result only if the index links to it or its README has `MIN_LIST_LINKS` (50) distinct outbound links (`countOutboundLinks`); topics are self-applied, so product repositories tagged `awesome` would otherwise pass. Measured: products stop near 30, unindexed lists start past 80. An unreadable README drops only that candidate; a rate limit fails the search. A failed trending page is left out of the ranking; every page failing is an error.
- Activity (`activity.ts`) runs one GraphQL query per found repository, alongside its star history, never batched (10 repositories × 3 searches exceeds GitHub's resource budget). It searches by the canonical `nameWithOwner` (`docs/LESSONS.md`) over items opened 14–365 days ago: counts for the whole window and open within it, plus the newest 100 items, whose closer (`ClosedEvent` actor `Bot` = unhandled) and maintainer replies (`OWNER`/`MEMBER`/`COLLABORATOR`) give the estimates. Backlog = (open + closed × the sample's bot-closed share) / opened. Medians and the unanswered share need 5+ sampled items, else null. Committers count distinct login (else email) over the newest 100 commits in 90 days. A refused activity query fails only its repository.
- Star lists (`star-lists.ts`) are read 10 lists per query with their first 100 repositories, and a fuller list is paged by its node id; 32 lists in one query answer 502. They refresh with the stars, and a failed read fails the stars refresh like a failed `starred()`. The Stars view offers a star list select once any entry has a list.
- List filters: a null share (backlog, old open, unanswered) passes its limit, a null median (handle, merge days) fails it, and an entry without metrics fails every metric filter.
- `Store` drops cached metrics when `METRICS_VERSION` in `store.ts` exceeds the database's `user_version`; raise it whenever `RepoMetrics` changes shape.
- Cache freshness: lists, metrics, and README link counts 24h, stars 1h, trending 1h (in memory), a failed repository 1h, discovery 10 min, translations 7 days. Metrics drain in the background through a pool of `POOL_SIZE` (10) repositories in flight: each batch lookup fills free slots, then every repository finishes its star history and activity on its own, so a slow one holds up only its slot. A rate limit or propagated error pauses new lookups (until reset, else 1 min) and leaves the repository queued. The API returns what it has plus a `pending` count and the UI polls.
- Health labels, first match wins: `dead` (archived, or no commit in 365 days), `rising` (commit within 90 days, under 2 years old, and 50+ stars in 30 days or 5%+ growth with 10+), `mature` (3+ years, 1000+ stars, commit within 180 days, backlog ≤ 25%), `active` (commit within 90 days, and 5+ commits in 90 days or a median handle time of 7 days or less), else `stale`. `tests/health.test.ts` pins each rule; change both together.
- Per-repository failures stay per-repository: a refused GraphQL batch is split until the failing repository stands alone, and a refused star history fails only its repository. Rate limits (secondary limits included, waited out for a minute), network errors, and a 5xx that fails every repository in the whole batch propagate and pause the queue instead of caching failures. The UI keeps polling through a failed request while metrics were pending.

## Work Guidance

- Read `docs/LESSONS.md` before changing a GitHub query: GraphQL partial refusals and the stargazer restriction both fail silently.
- A finished library with no commit in a year reads as `dead`; that is a known limit of commit-based activity, not a bug.

## Verification

- `npm test` (vitest over `tests/`), `npm run typecheck`, `npm run lint`, `npm run build`; `scripts/check` at the root runs all of them.
